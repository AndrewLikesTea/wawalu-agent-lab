Closes #2702.

The Releases page defines one word for the releases that keep no reasoning — "A release is covered when it links at least one decision the decision log holds; every other release is uncovered." — and then labels the list of them with a different sentence: "Releases with no linked decision in this log". That heading is a second way of saying a word the page has already taught, and it only names one of the two ways a release gets onto the list. A release with a link that points at a decision this log does not hold is on that list too, and the heading said otherwise.

Copy only. Three strings, no behaviour, no new control, no CSS.

## The change

| | Before | After |
|---|---|---|
| Heading (`#coverage-gap-worklist-title`) | Releases with no linked decision in this log | **Uncovered releases** |
| New sentence under it (`#coverage-gap-worklist-rule`) | — | **A release is on this list when it links no decision at all, or when every decision it links is one this log does not hold.** |

The new sentence states membership rather than restating the definition: the heading now carries the term, so the sentence says who is on the list — nothing linked, or everything linked pointing at a record this log does not hold. Those are exactly the two kinds `coverageGaps()` produces (`unlinked` and `dangling`), and each row below already names its own kind in words.

It is authored in the markup, not written by script, because it is true of the list before any of it is drawn — the same reason the coverage definition above is authored.
