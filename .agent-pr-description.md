Closes #2682.

The Releases page's "Copy both numbers as a sentence" control handed over four lines whose scope read "the Shiplog releases page" and whose provenance read "Counted here: 1 example record and 2 you added." Forwarded to someone who was not on the call, that is a count of releases with no statement of what an example record is — so the figure read as a claim about a real team's release history. And the only way to find out what the control would say was to press it and paste somewhere.

Two changes, one builder:

- **The sentence stands alone.** `reasoningProofSummaryLines()` is the new single source; `reasoningProofSummary()` is `lines.join("\n")`.
- **The sentence is on screen.** A copy-by-hand region (`#reasoning-proof-copyable`) renders the same array, one list item per line, directly above the control.

## The copied sentence, verbatim

Six lines. With three releases loaded, one of them a seeded example and one linking a decision the log holds:

```
Shiplog releases: 1 of 3 releases in this release log links at least one decision the decision log holds.
A link pointing at a decision the decision log does not hold does not count. Neither does a release with no linked decision.
Counted here: 1 example record and 2 you added.
Example records counted here are invented to demonstrate Shiplog and use no customer or production data.
Counted over every release loaded in the browser it came from, not a filtered view.
Source: the Releases page of the Shiplog site, at releases.html.
```

Lines 1–3 are the existing wording, unchanged. Lines 4 and 6 are new. Line 5 is the old scope sentence rewritten: it was "Counted over every release loaded on the Shiplog releases page, not a filtered view." Pasted into a mail, "this browser" (the page's own wording for the same fact) is the *recipient's* browser, so the scope now names the browser as somewhere else and line 6 carries the page.

- **Placement.** Under `#coverage-gap-definition` and above `.shiplog-proof-share`, asserted against **rendered** body text, not source order. It also makes `REASONING_PROOF_COPY_FAILED_STATUS` ("The same sentence is above this button.") literally true for the whole sentence rather than for its first line.
- **Lifecycle.** Ships `hidden` with an empty list and `aria-busy="true"`; revealed by the same call that paints it. No placeholder and no zero reaches the served bytes. Over a refused read the counts *do* exist — they are nothing — so the region is painted and line 1 is "Shiplog releases: No releases are loaded here, so there are none to count." with no digit in it. Pinned both ways.
- **The control is untouched.** Same label, same `disabled` in the markup, same `aria-describedby`, and `#reasoning-proof-copy-availability` still ships "The copy control becomes available once the figures are counted." verbatim and is still emptied as the control goes live. A test asserts all five.
- **No tab stop.** Nothing in the region is focusable, so the page's tab order is the one it had.
- **Labelled, not headed.** `aria-labelledby` on the list points at the visible paragraph above it, which names the control. A heading would have been the block's second `h2`, which an existing test forbids. `role="list"` is explicit because CSS removes the markers.
- **Not a live region, deliberately.** `#reasoning-proof-claim` is already `role="status" aria-live="polite"` and carries line 1 verbatim, so making this one live too would read the same two figures to a screen reader twice per count — once bare, once inside six lines of provenance. `aria-busy` carries the wait instead, which is exactly how `index.html`'s `#evaluation-summary-preview` — the same component, a payload previewed beside its copy control — already does it. Nothing here is assertive. This is the one place the acceptance criteria asked for a polite announcement and I did not add one; the reasoning is in the markup comment and in `renderReasoningProofSentence`'s docblock, and a test pins the absence so a future change has to argue with it rather than drift.
